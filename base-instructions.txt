Hi buddy, we have a very long way ahead of us. Here is an application I wrote long ago and still using daily, it is very useful to me. It is a password manager. It is a frontend only application written in TypeScript, that runs purely in the browser, on desktop or mobile phone, it does not need backend, it is standonle, just like a "rich-client" but running in the browser.
I want to modernize it and simplify it, so I want to rewrite it, in C# 14 / .NET 10 in Blazor. The requirements are that it must remain fully client-side only and work without backend at all, and still working in browser on desktop and mobile phone (it's ok if it does work on garbage mobile browser that do not support Blazor). Today, the code is compiled to static files hosted on GitHub Pages and it works fine. For heavy CPU-bound code such as cryptographic code, I think we will keep code written in JS (let's convert the actual TypeScript code to JS code so we do not depend on shitty webdev tools anymore, such as webpack or else, and no need TypeScript compiler anymore), for C#/JS interaction, we will need interop and that is fine.
I want to keep the tooling for building the application as simple as just loading the project in an IDE and build, or run a simple command just as 'dotnet build' to build it.
Another constraint is to simplify the UI and app usage. The application stores all information in a JSON file (called 'the vault') that is pushed to a private git repository, this allows the application to store the vault virtually anywhere and thanks to git, it is always possible to go back in time thanks to versioning and never lose important data. Currently the application have two different types of elements stored in the vault, "passwords" and "ciphers", passwords are auto-generated based on the master key and a public part, the public part can be decided by the user when the user needs to produce predictable password (for example, to regenerate the password without having access to the vault, in case of need to access the service that stores the vault itself). The problem with passwords is that the outcome cannot be decided because it is a hash of the master key and the public part, so I want to obsolete it, ciphers have random in the outcome, so encrypting the same value with the same key always produce different output, so they cannot be used to generate predictable password. If we could have an option to generate ciphers without random, it would be great but probably insecure. I think the best idea is to keep the notion of predictable 'password' but just hide them behind a checkbox on the UI. Currently, the application UI is kind of hard to understand, since there is a tab to create (and edit somehow) passwords, another tab for ciphers, and a tab to see the content of the vault and search inside, it's not user friendly at all so this should be reworked too. Today, the structure of the vault is hierarchical, it is very useful to organize data properly, but the counterpart is that it makes it hard to re-organize for the user, on a mobile phone for example where drag-and-drop can do the job but hard to perform on a small screen, and very hard to implement for us. So I'm considering having a flat structure like most of password managers, like Bitwarden. For the vault file access (git repo) today the procedure is very complicated and not user friendly at all, I have to go to GitHub and generate a PAT (personal access token) that is encrypted with the master key and stored in local storage, for security reason, I never use infinite lifetime tokens so every 90 days, I have to go back to GitHub settings page, regen a new token ad store it in the application, and because I use the app across many desktop computers and mobile phones, it can be a mess, and a nightmare for non computer scientist users. I also want to simplify this process. I want to use OAuth or OIDC to get read/write tokens for git operations to read and push the vault file to the git repo, but nowadays on GitHub, the only flow that allows this is insecure due to no support for PKCE feature, other flows have problems such as blocking calls with CORS, the application being a browser app, it runs in the browser but on another domain.
Please read the whole code and try to understand what it does and how it does it. Note that the 'cli' directory is very old C# code and can probably be ignored, the 'docs' directory is the compiled version of the code to be hosted on GitHub Pages, the code itself is mainly in the 'web' directory.
Do not hesitate to ask me questions if you need further information.
